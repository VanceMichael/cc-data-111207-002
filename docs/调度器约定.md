# 调度器约定

`scheduler.py` 把请求器扩展为可嵌入采集进程的分层额度调度器。所有确定规则如下。

## 三层额度

出口（egress，全部调用）、凭据组（credential，按凭据名）、租户（tenant）三层滑动窗口，本地镜像服务端 `(now-window, now]` 计数。发送必须同时满足三层；任一层的额度耗尽或冷却生效都进入等待，`waiting()` 逐请求报告阻塞作用域与就绪时间。

## 429 与 Retry-After

- 429 不消耗额度：退还本次本地预留，按 `X-Quota-Scope` 指定作用域冷却。凭据组冷却被同凭据的全部租户共享；出口级暂停阻塞所有租户。作用域缺失或未知时按出口级处理（最保守）。
- 429 是服务端的明确拒绝，任何请求（含不可重放）都可安全重排。
- `Retry-After` 解析规则（`parse_retry_after`，返回等待秒数与规则说明）：
  - 缺失或格式错误 → 默认冷却（`default_cooldown`，未配置时取该作用域窗口）；
  - 非负整数 → 秒数；HTTP 日期（无时区按 UTC）→ 与当前时间的差；
  - 秒数为 0 或日期已在过去 → 0，不等待；
  - 超过 `max_cooldown`（默认 3600 秒）→ 截断。

## 重试与副作用

- 传输错误携带 `sent` 标志：发送前失败（`sent=False`）未占用服务端额度，退还预留并重排；发送后断连（`sent=True`，含执行超时 `TransportTimeout`）保留预留。
- `sent=True` 时可重放请求自动重排（窗口内会出现新旧两条预留，属保守估计）；不可重放的副作用调用不自动重发，停放为 `unknown`，由人工核对后 `resume()` 重排或 `abandon()` 放弃。
- 传输错误重试计入 `max_attempts`（默认 8），超限置 `failed`；429 重排不计。

## 取消、超时与额度预留

- 排队中取消：直接移除，不产生预留。
- 飞行中取消：标记后等待结局，响应到达即丢弃（结果不保存），已产生的预留不退还。
- 执行超时按"可能已发出"处理：保留预留，按重放性决定重排或停放。

## 进程退出与恢复

`state_dir` 下的 `journal.jsonl` 记录 submit/sent/throttled/finished/transport_error 等事件（每条 fsync）。用相同 `state_dir` 重新构造 `Scheduler` 即恢复：

- 待执行项重新入队，租户内保持原顺序；
- 已发出但响应尚未保存的请求：预留保留（不简单退还），可重放者重排到队首，不可重放者停放 `unknown`；
- 已完成的响应体、未过期的冷却一并恢复；
- 租户虚拟时间（公平性状态）不持久化，重启后从 0 重新累计。

## 公平性

各租户维护虚拟完成时间，每次发送推进 `1/weight`；调度器在有资格的队首请求中选择虚拟时间最小者（并列按提交顺序）。权重 3:1 时份额约为 3:1，低权重租户每个窗口都能获得发送机会，不会被无限饿死。新租户从当前最小虚拟时间起步，不补账也不获额外提升。

## 接口

`submit`（提交，可传 `Request` 或 fixtures 同构字典）、`cancel`、`step` / `run_until_idle`（驱动执行，等待时通过注入的 clock 休眠）、`waiting`（等待原因）、`status` / `result`、`resume` / `abandon`。`clock`（`SystemClock` / `ManualClock`）与 `transport`（`(request, timeout=...) -> Response`，失败抛 `TransportError`）均可注入，本地样例用逻辑时钟拨快，不必真等。
